**Objetivo:** un comando que lanza los siete agentes del enjambre con el Claude Agent SDK en orden fijo, para solo y deja `eventos.jsonl`; y una página local en pixel art que lo reproduce o lo sigue en directo.

**Stack:** Python 3.12.14 (`.venv` ya creado), `claude-agent-sdk` 0.2.163, `pytest`, `pytest-asyncio`, cliente LogCentral (`/data/logcentral/packages/client`). JS sin build ni dependencias; pruebas JS con `node --test` (Node 22.18).

## Foco de revisión

Lo que la spec implica, ninguna prueba "natural" cubre y más probablemente muerda. Cada línea tiene su prueba añadida en la tarea indicada.

1. **Escapar del muro por ruta relativa o symlink** (`../../etc/passwd`, `fichas/../../../data/agora/x`, symlink en `SALIDA` apuntando al repo): debe denegarse. → Tarea 3.
2. **Un lector cuelga o falla mientras los demás siguen**: el run espera a todos, no lanza al trazador y termina con `fallo:lector-de-pieza:<id>:<estado>`; el jsonl queda bien formado. → Tarea 6.
3. **Líneas de eventos entrelazadas o cortadas** con 8 lectores escribiendo a la vez, y el SSE leyendo una línea a medio escribir: cada línea leída debe ser JSON válido. → Tareas 5 y 8.
4. **`piezas.md` con ids raros** (mayúsculas, espacios, backticks, tabla vacía): no se lanza ningún lector y el run para con motivo legible, en vez de crear `fichas/` con nombres arbitrarios. → Tarea 4.
5. **Path traversal en el servidor de la pantalla** (`/api/fichero/agora/run/../../../../etc/passwd`, `%2e%2e`): 404, nunca contenido. → Tarea 8.

### Tarea 3: El guardia (D8)

**Ficheros:** Crear `enjambre/guardia.py`, `tests/test_guardia.py`

**Interfaces:**
- Produce:
```python
def ruta_de(herramienta: str, entrada: dict) -> str | None
def permitido(rol: str, herramienta: str, ruta: str | None, repo: Path, salida: Path) -> tuple[bool, str]
```
`ruta_de` saca la ruta de la entrada de la tool: `Read`/`Write`/`Edit` → `file_path`; `Glob`/`Grep` → `path` (puede faltar → `None`). `permitido` con `ruta=None` evalúa `salida` (es el `cwd`, §3.3). Rutas relativas se resuelven contra `salida`. Siempre `Path(...).resolve()` antes de comparar con `is_relative_to`, para que `..` y symlinks no escapen. `motivo` es una frase corta en español; vacía si `ok`.

### Tarea 5: Eventos y tipos compartidos

**Ficheros:** Crear `enjambre/tipos.py`, `enjambre/eventos.py`, `tests/test_eventos.py`

**Interfaces:**
- Produce (`tipos.py`):
```python
EstadoFinal = Literal["terminado", "bloqueado", "error", "timeout"]

@dataclass
class Resultado:
    estado_final: EstadoFinal
    respuesta: str = ""
    modelo_real: str | None = None
    duracion_s: float = 0.0
    tokens_in: int = 0
    tokens_out: int = 0
    coste_usd: float = 0.0
    num_herramientas: int = 0

@dataclass
class Contexto:
    repo: Path
    salida: Path
    eventos: "Eventos"
    timeout_s: float = 600
    max_turns: int = 60

Lanzar = Callable[["Agente", str, str, Contexto], Awaitable[Resultado]]
# lanzar(agente, instancia, encargo, ctx) -> Resultado
```
- Produce (`eventos.py`):
```python
class Eventos:
    def __init__(self, ruta: Path, run: str): ...
    def emitir(self, tipo: str, agente: str | None = None, **campos) -> dict   # escribe y devuelve el evento
    def cerrar(self) -> None
```
`emitir` añade `t` (`datetime.now().isoformat(timespec="milliseconds")`, hora local), `run`, `tipo` y `agente` si no es `None`; escribe una línea JSON (`ensure_ascii=False`) **en una sola llamada `write` seguida de `flush()`**, protegida con `threading.Lock` (los lectores emiten desde el mismo bucle asyncio, pero el hook del SDK puede venir de otro hilo). Abre el fichero en modo `"a"` con `encoding="utf-8"`, `buffering=1`.

```python
async def orquestar(repo: Path, salidas: Path, lanzar: Lanzar, *, tope_usd: float = 5.0,

                    run: str | None = None) -> dict      # devuelve el evento run_fin
```

**Comportamiento de `orquestar`** (§3.5, al pie de la letra):
- `run` por defecto `f"{repo.name}-{datetime.now():%Y%m%d-%H%M}"`; `salida = salidas / repo.name / run`; si existe → `FileExistsError`. Crear `salida` y `Eventos(salida / "eventos.jsonl", run)`.
- `run_inicio` con `repo`, `salida`, `params`, `roles = {rol: cargar(rol).modelo}`; `estado=esperando` para cartografo, despiezador, trazador, redactor, verificador, novato.
- Encargo: líneas `CLAVE=valor` (`REPO`, `SALIDA` siempre; `PIEZA`, `MODO`, `VUELTA` según rol). Al redactor y al novato **no** se les pasa `REPO` (D2).
- Antes de cada `lanzar`: si `coste_acumulado > tope_usd` → `run_fin motivo="tope_coste"`. Tras cada uno, sumar `resultado.coste_usd`.
- Cada `lanzar` va precedido de `lanzado` (`rol`, `modelo_pedido`, `encargo`) y seguido de `respuesta` y `fin_agente` (campos del `Resultado`). **Estos tres los emite `orquestar`, no `lanzar`**; `lanzar` emite solo `estado`, `herramienta`, `denegado`, `fichero`, `aviso`.
- Paradas: agente con `estado_final != "terminado"` → `motivo=f"fallo:{instancia}:{estado_final}"`; fichero esperado ausente → `motivo=f"falta:{ruta_relativa}"`; `SalidaIlegible` en piezas → `motivo="piezas_ilegibles"`.
- Lectores: `asyncio.gather(*..., return_exceptions=True)`; una excepción cuenta como `error`. Esperar a todos, luego comprobar.
- Vuelta: emitir `vuelta(n)`; verificador y novato en paralelo; copiar `verificacion.md` y `dudas.md` (los que existan) a `salida/vueltas/<n>/` (D13); aprobado si `fallos == 0 and veredicto == "listo"` → `motivo="aprobado"`; si `n > max_vueltas` → `motivo="tope_vueltas"`; si no, redactor `MODO=revision`, `n += 1`.
- `run_fin` lleva `motivo`, `vueltas` (número de pasadas verificador+novato hechas), `coste_total_usd`, `duracion_s`. Siempre se emite, también en `asyncio.CancelledError` (`motivo="interrumpido"`, y re-lanzar) y en excepciones no previstas (`motivo=f"excepcion:{tipo}"`, `log.exception(...)` con `obtener_log()`, y re-lanzar). Usa `try/finally` para cerrar `Eventos`.
- `main`: `asyncio.run(orquestar(...))`; imprime una línea `run motivo vueltas coste ruta`; devuelve 0 si `aprobado`, 130 si `interrumpido` (capturar `KeyboardInterrupt`), 1 en otro caso. `--falso` usa `hacer_lanzar_falso(retardo_s=0.5)`; sin `--falso` importa `enjambre.lanzador.lanzar` **dentro de `main`** (para que las pruebas no importen el SDK).

**`hacer_lanzar_falso`:** por defecto, cada rol escribe sus ficheros de pega en `ctx.salida` (cartografo `mapa.md`; despiezador `piezas.md` con un `## Resumen` de 3 ids `a-uno`, `b-dos`, `c-tres`; lector `fichas/<PIEZA>.md`; trazador `flujos.md`; redactor `articulo.md` y en revisión añade a `cambios.md`; verificador `verificacion.md` con `- Fallos: 0`; novato `dudas.md` con `## Veredicto\n\`listo\``), emite por el camino `estado` leyendo/escribiendo, `herramienta` y `fichero` como lo haría el real, espera `retardo_s` entre eventos, y devuelve `Resultado("terminado", respuesta=..., modelo_real=f"claude-{agente.modelo}-falso", coste_usd=0.01, ...)`. `guion` permite sustituir, por instancia (`"lector-de-pieza:b-dos"`, `"verificador"`…), una lista de resultados o funciones que se consumen por orden de llamada; una función recibe `(agente, instancia, encargo, ctx)` y puede escribir ficheros distintos (p. ej. `Fallos: 2`) o lanzar.

### Tarea 8: Servidor de la pantalla

**Ficheros:** Crear `enjambre/pantalla.py`, `tests/test_pantalla.py`

**Interfaces:**
- Produce:
```python
def crear_servidor(host: str, puerto: int, salidas: Path, estaticos: Path) -> ThreadingHTTPServer
def main(argv: list[str] | None = None) -> int     # --host 100.87.64.121 --puerto 8790 --salidas <repo>/salidas
```

Rutas de §5.1, con estos detalles:
- `/` → `estaticos/index.html`; `/static/<f>` → `estaticos/<f>` (solo nombres simples, `[A-Za-z0-9._-]+`).
- `/api/runs` → `[{"repo","run","inicio","motivo"}]`, más recientes primero; `inicio` = `t` del primer evento; `motivo` del `run_fin` o `null`.

- `/api/fichero/<repo>/<run>/<ruta...>` → `text/plain; charset=utf-8`.
- Toda ruta se decodifica (`urllib.parse.unquote`) y se resuelve; si no cae dentro de `salidas.resolve()` (o de `estaticos` para `/static`) → 404. `daemon_threads = True`.

**Principio:** el servidor sirve la página y lanza un subproceso del que solo sabe lo que necesita para pintar: su `pid`, el repo y el `run`. Nunca importa `enjambre.orquestar` ni el SDK.

**Ficheros:** Modificar `enjambre/orquestar.py` (`--run`), `enjambre/pantalla.py`, `pantalla/index.html`, `pantalla/escena.js`; `tests/test_orquestar.py`, `tests/test_pantalla.py`.

**Interfaces:**
- `orquestar.main`: nuevo argumento `--run <nombre>` que pasa a `orquestar(run=...)`. Sin él, el comportamiento de siempre.
- `pantalla.crear_servidor(host, puerto, salidas, estaticos, *, raiz_repos: Path = Path("/data"), comando: Callable[[list[str]], list[str]] | None = None, dir_logs: Path = <repo>/logs/lanzamientos)`. `comando` recibe los argumentos de `orquestar` y devuelve el argv completo; por defecto `[sys.executable, "-m", "enjambre.orquestar", *args]`. Las pruebas lo sustituyen por un proceso de mentira.
- Rutas nuevas:

| Método y ruta | Cuerpo | Respuesta |
|---|---|---|
| `POST /api/lanzar` | JSON `{"repo": str, "tope_usd": float, "max_vueltas": int, "falso": bool}` | 202 `{"repo": "<nombre>", "run": "<run>"}` · 400 validación · 403 sin cabecera · 409 ya hay uno en marcha |
| `POST /api/parar` | — | 202 si había run en marcha (le envía `SIGINT`) · 409 si no |
| `GET /api/lanzador` | — | `{"en_marcha": bool, "repo": str|null, "run": str|null}` |

**Reglas:**
- **Anti-CSRF:** `POST` exige `Content-Type: application/json` y la cabecera `X-Enjambre: 1`; sin ellas → 403. (Otra web abierta en el navegador de Josem no puede mandar esa combinación sin preflight CORS, y el servidor no responde CORS.)
- **Validación:** `repo` resuelto (`Path(repo).resolve()`) debe estar bajo `raiz_repos.resolve()` y ser un directorio; `0 < tope_usd <= 10`; `0 <= max_vueltas <= 3`; `falso` booleano. Cualquier otra cosa → 400 con `{"error": "<motivo>"}`.
- **Un run a la vez:** se guarda el `Popen`; "en marcha" = `proc.poll() is None`.
- **Nombre del run:** lo decide el servidor, `f"{repo.name}-{datetime.now():%Y%m%d-%H%M%S}"` (con segundos, para no chocar), y lo pasa con `--run`.
- **Subproceso:** `subprocess.Popen(argv, cwd=<repo del enjambre>, start_new_session=True, stdout=log, stderr=subprocess.STDOUT)`, con `log` = `dir_logs/<run>.log`. `start_new_session` hace que el run sobreviva a un reinicio de la pantalla (que entonces lo olvida: `en_marcha` volverá a `false`; aceptado en el POC).
- **Parar:** `proc.send_signal(signal.SIGINT)`; el orquestador ya lo convierte en `run_fin` con `interrumpido`.
- **Directo con el fichero aún sin crear:** `/api/directo/<repo>/<run>` espera hasta 30 s a que aparezca `eventos.jsonl` antes de dar 404.

**Página:** en la portada (sin `?run=`), un formulario encima de la lista de runs: ruta del repo (texto, por defecto `/data/agora`), tope en $ (5), vueltas (2), casilla "falso (sin gastar)". Botón Lanzar → `fetch('/api/lanzar', {method: 'POST', headers: {'Content-Type': 'application/json', 'X-Enjambre': '1'}, body})` → si 202, navega a `?run=<repo>/<run>&modo=directo`. En modo directo, botón **Parar** visible mientras no llegue `run_fin`. El botón Lanzar se desactiva si `/api/lanzador` dice `en_marcha`.
